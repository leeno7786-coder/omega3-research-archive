Omega 3.0 — Terminal Agent Execution Contract
1. System Overview

Omega’s Terminal Agent is a deterministic execution layer that converts structured task contracts into real-world actions (code generation, file operations, tool execution), while learning from outcomes and updating system capability.

The system is composed of:

BrainLoop (L1) — Translates user intent into structured task contracts
AutoLoop (Internal Cognition) — Plans execution and decides learn vs execute
Terminal Agent (Execution Core) — Performs tool calls and validates outputs
Guardian System — Governs all memory writes and sensitive actions
Memory System — Stores knowledge, workflows, and execution results
Neuromodulation System — Influences execution behavior (not control flow directly)

4. AutoLoop Planning Contract

AutoLoop converts Task Contract into a DAG of steps.

Step Schema
{
  "step_id": "string",
  "type": "research | design | scaffold | implement | test | refine",
  "inputs": [],
  "outputs": [],
  "tools": [],
  "status": "pending | running | complete | failed",
  "retry_count": 0
}
Planning Rules
Always produce a DAG (not linear chain)
Respect dependencies between steps
Insert research phase if knowledge gap detected
Reuse prior workflows if similarity > threshold
5. Learn vs Execute Decision
IF memory_recall(domain) == empty OR strength_index < threshold:
    mode = "learn"
ELSE:
    mode = "execute"
Learn Mode
Use web_fetch
Extract structured knowledge
Submit memory writes through Guardian
Execute Mode
Use existing memory
Perform tool-based actions
6. Terminal Agent Execution Cycle

For each step:

1. Retrieve relevant memory
2. Rerank candidates (embedding + reranker)
3. Generate tool calls
4. Execute tool(s)
5. Validate results
6. Emit telemetry
7. Submit memory write → Guardian

10. Workflow Persistence

Store DAG + outcomes:

{
  "workflow_id": "uuid",
  "steps": [],
  "success_rate": 0.0
}
Reuse Rule
IF similarity(new_task, stored_workflow) > threshold:
    reuse workflow
11. Guardian Integration

All writes go through Guardian:

decision = guardian.decide_request(request)

IF decision == ALLOW:
    commit
ELSE IF decision == FLAG:
    commit_with_flag
ELSE:
    reject
12. Failure Handling Policy
IF step fails:
    retry_count += 1

IF retry_count > max_retries:
    IF learning allowed:
        switch to learn mode
    ELSE:
        escalate to user

Arousal
Increase exploration

Plasticity
High → allow learning
Low → suppress memory writes

🔧 Omega 3.0 — Voice Model Tool Invocation Contract (Gemma E2B)
1. Core Principle

The voice model is NOT an agent.
It is a structured emitter of tool intents under strict schema.

No freeform tool calls
No implicit execution
No side effects
Only declarative intent → execution layer acts
2. Gemma-Compatible Tool Call Format

Gemma models typically perform best with explicit JSON blocks embedded in text, not hidden function-call APIs.

Canonical Output Format
{
  "type": "tool_call",
  "tool_name": "string",
  "arguments": {},
  "call_id": "uuid",
  "reasoning": "short justification"
}
Rules
MUST be valid JSON
MUST be top-level (no nesting in prose)
MUST contain all fields
reasoning is short and controlled (not chain-of-thought)
3. Multi-Tool Calls (Batch Execution)

Gemma can emit multiple calls in sequence:

{
  "type": "tool_batch",
  "calls": [
    {
      "tool_name": "web_fetch",
      "arguments": { "query": "FastAPI tutorial" },
      "call_id": "call_1"
    },
    {
      "tool_name": "write_file",
      "arguments": {
        "path": "app.py",
        "content": "..."
      },
      "call_id": "call_2"
    }
  ]
}
4. Tool Registry Contract

The model MUST only call tools defined in registry.

Example Registry
{
  "tools": [
    {
      "name": "web_fetch",
      "description": "Fetch and extract structured data from the web",
      "arguments_schema": {
        "query": "string",
        "extract": ["string"]
      }
    },
    {
      "name": "write_file",
      "description": "Write content to file",
      "arguments_schema": {
        "path": "string",
        "content": "string"
      }
    },
    {
      "name": "run_command",
      "description": "Execute terminal command",
      "arguments_schema": {
        "command": "string"
      }
    }
  ]
}
5. Voice Model Prompt Contract

Gemma must be instructed with strict output rules.

System Instruction (critical)
You are Omega's Voice Execution Interface.

You do NOT execute tasks.
You ONLY emit structured tool calls in valid JSON.

Rules:
- Output ONLY valid JSON when calling tools
- Do NOT include explanations outside JSON
- Use only tools from the registry
- Arguments must match schema exactly
- If no tool is needed, respond normally

Never hallucinate tools.
Never skip required fields.

A) Tool Call Mode

When action is required:

{

    "path": "main.py",
    "content": "print('Hello World')"

7. Execution Boundary (CRITICAL)

The model:

❌ DOES NOT:

execute commands
write files
access system

✅ ONLY:

emits structured intent
8. Terminal Agent Responsibility

The Terminal Agent:

Validates JSON
Verifies tool exists
Validates arguments
Executes tool
Returns result
9. Tool Result Feedback Loop

After execution, results are returned to model:

{
  "type": "tool_result",
  "call_id": "abc123",
  "status": "success",
  "output": "File written successfully"
}

Model then decides next step.

10. Error Handling Contract

If tool fails:

{
  "type": "tool_result",
  "call_id": "abc123",
  "status": "error",
  "error": "File path invalid"
}

Model must:

retry OR
choose alternative tool OR
escalate
11. Determinism Constraints

To prevent drift:

Temperature: LOW (≤ 0.3)
Max tokens: bounded
JSON schema validation enforced
Reject malformed outputs
12. Safety + Guardian Hook

Before execution:

IF tool affects filesystem OR memory:
    route through Guardian
