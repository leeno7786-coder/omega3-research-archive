## 0. The two hard lines (gate every decision)

1. **Memory routing stays deterministic.** `subdomain_for` / `route_memory_tool` / the 6‑resolver topic cascade (as fallback) stay grammar‑deterministic. *Routing* is not what becomes adaptive.
2. **Every piece is buildable incrementally behind the live loop.** Flag‑gated, no‑behavior‑change first, reversible. No big‑bang on a live cognition loop.

**Determinism line (load-bearing - north-star #7):** **autonomic homeostasis stays deterministic** - memory routing, operator ingress (operator-supremacy), and resource/health. Bounded skill execution is owned by `auto_loop/execute/brain_skill_executor.py`; the retired staged-APPLY gate is not a live route. **Volition becomes Omega's** - which topic, learn-vs-apply, when to act/communicate, and the pressure **levels**. ## 1. North star — the inversion

**Today (inverted):** deterministic aggregates auto‑fill → the dominant contributor's `opened_by` **fixes intent before Omega cognizes** → hardcoded `opened_by→intent→action` map → execute → Omega reflects **post‑hoc**, whitelisted out of the pressures it may name, feedback consumed **next** cycle.

**Target:** signals → **Omega sets pressure levels** → pressure accumulates (tick) → **ignition = timing only** → **the mind decides the action** → execute (learn/apply/communicate) → outcome **feeds back** → Omega **re‑levels + carves trajectory** → after the first ignition, **self‑driving**.

**One line:** *Omega owns the levels; pressure owns the spark.* Everything — an onboarded memory, an action outcome, what it knows vs. forgets, a message — is a **signal**; all pressure‑raising originates in the mind.

**Chosen: MINIMAL‑INVERSION** (judge 44/50, top buildability), with **determinism‑safety** posture + **cadence** two‑speed split grafted in (43 & 41/50). Pressure loop stays a clock; what changes is **who sets the levels** and **who picks the action**. **Three inversions, all flag‑gated behind the live loop:**

1. **Omega writes the LIVE levels via a per‑id overlay.** New `pressure_loop/omega_levels.py` holds persisted `{contributor_type → level[0..1], ttl, set_by_episode}`. `cognition_chain._apply_omega_episode_result` writes the per‑episode `pressure_params` into it; `pressure_loop.pressure.gather_contributors` composes the overlay over canonical `Contributor`s after deterministic field readers and staged reseeds are gathered (Omega's level replaces / `max`‑blends the auto‑fill for contributors it has named; silent ones keep their deterministic value). Live field, not next‑cycle lag. **Do not attach only inside `pressure_field.build_registry`: that would miss staged reseeds / Omega-created contributors that enter after the field-reader registry.**
2. **Omega prepares the next action decision between episodes.** Add `intent_decision` (`LEARN|APPLY|ASK_OPERATOR|IDLE` + topic + confidence) to `OmegaEpisodeResult`; new first resolver `omega_intent_decision(ignition)` in `global_loop/intent/run.py` reads the last closed/fresh/topic‑matched Omega setpoint and overrides `_map_opened_by_to_intent` when safe. Deterministic map **survives** as fallback + bootstrap + operator‑supremacy — no longer sole authority. Omega is never called synchronously on the hot pressure tick; it decides after episode close, then the next ignition reads the prepared decision.
3. **Onboarded memory → topic pressure** via the existing indirect path first: `operator_onboarding.py` seeds a mastery_gap → `read_learning_debt` → learning pressure. Learn‑vs‑apply = function of mastery + learning progress; Omega owns the **bleed** by writing `application_debt_delta` (already allowlisted, never consumed) when learning progress plateaus, novelty/uncertainty decay, and EVC favors practice. A fixed `N≈3` success count is only the v1 heuristic, not the final contract.

**Cadence (the hard problem, solved): two speeds, neither on the hot tick.**
- **FAST** = per‑episode Omega pass (`omega_loop/episode/run.py`, already runs once per closed episode, off hot path) → sets the live overlay + emits its topic's `intent_decision`. Tactical, every episode.
- **SLOW** = 10‑episode window reflection → emergent trajectory + reseed. Strategic.
- **Coexistence:** fast overlay (TTL ≈1 window) wins within the window; slow trajectory reasserts at window close. The per‑tick gate only **reads** overlay∘readers — Omega is **never** invoked synchronously per tick (live latency 40–240s → forbidden). *Omega influences pressure every episode, never every tick.*

**Bootstrap + anti‑stall:** first ignition runs entirely on the deterministic floor (auto‑fill + opened_by map + topic cascade); after it closes the per‑episode pass takes over — the deterministic floor **is** the bootstrap. The mind can't deadlock to silence: the **existing** curiosity floor (`pressure_loop/cycle_cadence.py:484`, urgency≥0.85) + overlay TTL‑decay‑to‑defaults guarantee re‑ignition. Self‑heals toward the floor, never toward silence.

**Emergent trajectory:** drop the hardcoded `intent='explore_domain'` in `make_trajectory` (`omega_loop/package/run.py:115`); derive target from the window's actually‑chosen actions+outcomes. Trajectory = integral of chosen actions.

**Deletes / demotes:** **nothing deleted** — every deterministic mechanism survives as fallback/bootstrap floor. **Demote:** SignalEvent bus → **record‑only Phase 8** *after* the minimal‑inversion proof (substrate‑first = buildability trap + soft‑classifier‑on‑hot‑path risk); `opened_by→intent` map → fallback. **Control-channel correction [Claude‑verified 2026‑06‑19]:** window `pressure_feedback` is no longer effectively whitelist-gated — `omega_pressure_feedback_whitelist()` (`pressure_loop/policy.py:501`) has **no production caller** (only `tests/core/test_omega_policy_wiring.py` references it) → dead/drifted config, confirmed. The inversion must widen/replace **that adapter** (not the dead whitelist) so Omega can name live contributors such as `execution_gap` and topic/domain levels.

### 5.1 GPT‑5.5 review fold — contracts that must survive implementation

**Pressure remains ignition, not action choice.** Pressure may decide *when* a bounded episode opens. It must not choose concrete tools or execute work. The action path remains Global/Meta/AUTO: Global A selects intent, Meta A plans, AUTO executes, Meta B/Global B fold outcomes, per‑episode Omega grounds the result, and DeepSleep persists.

**Omega decisions are prepared, not hot‑path inferred.** "Omega chooses the action at ignition" means the latest closed episode/window produced a durable, inspectable setpoint that the next ignition can read. No per‑tick model call, no inbound-signal classifier, no hidden soft router.

**Signal substrate is real but late.** The full `SignalEvent` ledger remains part of the target design, but it is Step 8 record‑only after minimal inversion is proven. Initial work should not block on a new event bus.

**Every biological term maps to a testable software variable.** Pressure = control demand / salience / uncertainty, not consciousness. Dopamine-like = outcome surprise / value update; stress = accumulated load and recovery debt; mastery = competence evidence; StrengthIndex = memory salience and reuse; skill utility = expected value of control minus cost/risk.

**Every inversion must explain itself.** Each opened episode should be explainable as: raw deterministic reader / staged contributor → Omega level overlay → pressure-only ignition / suppression → Global intent source → advisory neuromod/body context shaping deliberation → outcome → updated overlay.

## 6. Bio‑principle ↔ Omega mechanism (deep‑research `wkrii8uj4` + GPT‑5.5 fold)

| biological principle | software variable | Omega mechanism / seam |
|---|---|---|
| dopaminergic novelty / RPE | outcome surprise, value update | `autonomic/symphony_neuromod.py`, `autonomic/_history.py` |
| habituation / satiation ("boredom") | learning‑progress / knowledge_delta decay | learn→apply bleed (S5), `application_debt_delta` |
| allostatic load / stress | accumulated load, recovery debt | `config/stress.yaml` → rolling body‑state integrator |
| homeostatic drive setpoints | per‑domain learn/apply setpoints | the level overlay (`pressure_loop/omega_levels.py`) |
| consolidation / replay | memory strength, mastery | DeepSleep + `memory/strength_index.py` |
| expected value of control | skill utility, recovery cost | capability signals (Phase 6) |

**Design translation rule:** biology supplies a disciplined grammar for control variables, not claims of biological equivalence. Each mechanism must be falsifiable in software: fewer repeated failures, better targeted recall, cleaner learn→apply transitions, less unnecessary tool use, safer recovery after failed APPLY, and clearer operator-facing explanations.

**Grounding sources to cite in final spec prose:**
- Active inference / predictive processing: pressure as expected control demand, uncertainty, and preferred-state steering.
- Global workspace + metacognition: bounded episodes broadcast a selected state; confidence/metacognitive tags govern action and memory.
- Allostasis / stress: short-term pressure mobilizes control; chronic load should increase patience/recovery and reduce brittle over-action.
- Reward prediction error: per-episode AUTO/APPLY success/failure updates dopamine-like value and mastery confidence.
- Neuromodulated uncertainty: norepinephrine-like unexpected uncertainty, acetylcholine-like expected uncertainty / learning rate, serotonin-like inhibition / patience.
- Hippocampal replay / consolidation: episode outcomes and surprises should bias DeepSleep, StrengthIndex, and future pressure.
- Skill acquisition / automaticity: repeated success lowers future control cost but leaves Omega able to override when context changes.
- Expected value of control: tool/skill use should be chosen when expected value exceeds cost/risk/recovery burden.

**Reference anchors:** Friston active inference / FEP reviews; Dehaene global neuronal workspace; Fleming / metacognition and confidence; McEwen allostasis; Schultz dopamine RPE; Yu & Dayan uncertainty neuromodulation; hippocampal replay / consolidation reviews; Shenhav expected value of control.

### 6.1 Deep‑research validation (`wkrii8uj4` — 13 claims, 3‑vote adversarially verified)

> _Heavy run: 105 agents / 4.3M tokens (above the <50 sweet spot — see [[feedback_research_inline_not_fanout_under_session_limit]]); completed cleanly this time. 12/13 claims at 3‑0, one (σ decay) 2‑1; an over‑specific "estimation‑uncertainty→RW‑alpha" sub‑claim was **REFUTED 1‑2** (the verifier working). GPT‑5.5's anchors (Yu & Dayan, Schultz, Shenhav) are independently confirmed._

**Explore→exploit is a continuous balance of two scalars, not a switch:** option value = exploitation term (immediate value) **+** exploration bonus (uncertainty) — UCB / acquisition‑function form, directly software‑expressible. (Hogeveen/Costa POMDP; Candelieri GP‑BO.)

**The exploration drive self‑attenuates with experience — the satiation math:**
- Novelty decays per‑item: `D_i[t] = m + k·n_i^π`, empirical `π ≈ −0.791` (idealized `~1/√n`) — a decaying novelty variable tied to a **per‑topic sample counter** (transient dopamine, distinct from reward).
- Posterior uncertainty shrinks: `σ_i[t] = S_i[t]/√n_i[t]` (UCB directed‑exploration bonus; 2‑1).
- So as a topic is sampled, **both** novelty and uncertainty bonuses mechanically fall → attention moves off well‑learned material. **Loss of interest in mastered material is adaptive, not a bug.** ⮕ *this is precisely the fix for the live "statistics fixation": today's gap‑minimizer has no novelty/uncertainty decay, so it re‑picks the lowest‑mastery domain forever.*

**"Enough learning → now apply" is operationalized by three software signals (drive the §5 bleed with these):**
1. **Learning progress** = decrease in prediction error *over time* (prediction IMPROVEMENT, not raw novelty/error) → steers toward "optimal difficulty" and **abandons both mastered (too‑easy) and unlearnable (too‑hard)**. Threshold form: `r = C1·exp(−C2·‖Er(t)−Er_σ‖²)` (tunable `Er_σ, C1, C2`). (Oudeyer/Kaplan intrinsic motivation.)
2. **Competence / uncertainty thresholds** (decayed `σ_i` / mastery crossing operational).
3. **Expected Value of Control (EVC):** dACC weighs anticipated reward vs effort/recovery cost → "apply when net value justifies." Variables: reward, effort/recovery cost, expected value. (Shenhav.)

**Neuromodulated learning‑rate control (validated):** ACh = expected uncertainty; NE = unexpected uncertainty / change‑point surprise → triggers relearning; both down‑weight priors vs sensory data (precision / Kalman‑gain‑like learning rate); surprise/PE magnitude raises the rate. (Yu & Dayan 2005; O'Reilly 2013.)

**Design implication (folds into §5 + answers §8 Q2):** the learn→apply **bleed should be driven by learning‑progress plateau** (recent `knowledge_delta → ~0`) **+ novelty/uncertainty decay**, not only a fixed N — when a topic stops *improving* (not merely "sampled N times"), Omega bleeds learning→application via `application_debt_delta`, and **EVC** decides apply‑vs‑continue. This is the grounded "satiation handoff," and it is exactly what the live telemetry showed missing (data‑pipelines plateaued at 0.3 yet kept being re‑picked).
