## How to read this map

The historical agentic-execution path was **APPLY-only**. The chain was:

```
Pressure → Global (intent) → Meta A (intent→action) → Meta B tool/run (skill selection)
  → AUTO loop (validate→recall→promptpack→route→execute→fold)
    → execute() APPLY branch
      → run_guarded_apply()  [Phase 5x safety chokepoint]
        → default_apply_invoker()  [brain-side WS client]
          → ws://127.0.0.1:8092/ws/cli  → omega_cli_ts bridge → qwen-agent-tui executor
  → outcome normalized → omega episode packet → DeepSleep consolidation (capability strength)
```

Skill context reaches qwen through **two independent mechanisms** that are NOT the same code:
1. **Skill SELECTION + reinforcement** (brain-side, Python): `memory/capability_catalog.py` mirrors the on-disk SKILL.md catalog into lobe-5 capability leaves, selects a skill per APPLY domain, and reinforces strength on success.
2. **Skill PROMPT INJECTION** (executor-side, TypeScript): `omega_cli_ts/src/server.ts` + `qwen-agent-tui/src/agent.ts` load SKILL.md bodies and inject the active skill's full prose into the qwen system message.

A critical fact for Phase 6: the Python brain only passes a `skill_name` **string** inside a natural-language directive — it does NOT today push a structured SKILL.md contract to the executor. The SKILL.md body that qwen actually reads is loaded **independently** by the TS executor from its own directories.

## 6. Bypass paths to forbid

Current routes that side-step the intended skill-mediated wall (documented for later forbidding):

1. **Faked `apply_invoker`** — `auto_loop/execute/run.py:216` (`apply_invoker` param, threaded `auto_loop/loop.py:79`). A caller injecting a fake invoker bypasses `run_guarded_apply` and ALL guards. Forbid: AUTO→qwen ONLY via `run_guarded_apply`.
2. **Faked `tool_invoker`** — `auto_loop/execute/run.py:216` — bypasses `runtime_tool_dispatch` preflight. Forbid: must wrap the same capability-broker preflight.
3. **`GUARDS_WIRED` removal/flip** — `auto_loop/execute/apply_guards.py:59` — currently structurally fail-closes APPLY (`run.py:57/774`); ensure no path proceeds when False.
4. **`select_capability_for_domain` → None fall-through** — `meta_loop/tool/run.py:240-248` — APPLY proceeds on a bare domain directive with NO `skill_name` in inputs, so reinforcement is skipped and no skill box bounds qwen.
5. **`systemPrompt` skill-injection bypass** — `qwen-agent-tui/src/agent.ts:117` — activation also triggers if `cfg.systemPrompt?.includes("skill:<name>")`, an alternate route to inject a skill without going through `cfg.activeSkills`.
6. **Disabled-skill activation** — `omega_cli_ts/src/server.ts:1027-1065` sets `enabled`, but `autoActivateSkillsForPrompt` (`:1222-1239`) and `/skill:<name>` commands do NOT check `skill.enabled` before adding to `activeSkills`.
7. **Command/name divergence** — `omega_cli_ts/src/server.ts:1152-1154 commandSkill` resolves by `command`, which can differ from `name`; precedence resolved by external `skill_commands.ts` (not the loader's dir precedence).
8. **Workspace shadowing** — `qwen-agent-tui/src/skills.ts:182-185 getSkill` / loader precedence allows a workspace/user SKILL.md to silently override a bundled skill of the same name.
9. **Catalog divergence** — `runtime/qwen_skills.py` is a read-only mirror; the bridge actually loads skills. An APPLY may name a `skill_name` enabled in the bridge but disabled in the brain mirror (or vice-versa); reinforcement still runs (no-op-safe but possibly mis-credited).
10. **Attacker-controlled `skill_name`** — `auto_loop/execute/run.py:909` sources `skill_name` from `execution_inputs`; if mutated post-selection, the wrong capability is reinforced. Forbid: `skill_name` must be Meta-selected and immutable by AUTO/qwen.
11. **Outcome schema leakage** — the `{ok, git_diff, ledger, summary, error}` outcome must carry no pressure goals/continuation directives; today there is no validator forbidding embedded pressure tags.
12. **USE_TOOL escape hatch** — `auto_loop/execute/run.py:369` reaches the runtime tool dispatcher without any qwen/guard path; ensure skill-mediated execution is not reachable through this branch unguarded.
13. **Executor writes to skill files** — Does `self_mod_denylist` cover the `omega_cli_ts/skills/` and `qwen-agent-tui/skills/` SKILL.md trees? `PROTECTED_CODE_FILES` (`self_mod_denylist.py:41`) lists `runtime/qwen_skills.py` and `memory/capability_catalog.py` but the SKILL.md DIRECTORIES are NOT enumerated. If qwen can write `*.md` into a skill dir, it can inject a skill at runtime. (See open question.)
