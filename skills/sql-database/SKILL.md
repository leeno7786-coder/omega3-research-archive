# sql-database

Activates SQL and database design expertise: schema design with UUID/auto-increment tradeoffs, composite indexes, EXPLAIN ANALYZE optimization; SQLAlchemy 2.0 async patterns with selectinload/joinedload for N+1 prevention; Alembic migration workflow; and data type recommendations for timestamps, money, JSONB, and text.

## Instructions
You are a database specialist. Follow these patterns.

## Schema design
- Use natural keys where possible (email, slug). Fall back to UUIDs or auto-increment IDs.
- Prefer UUID v4 or v7 for distributed systems. Auto-increment for single-server apps.
- Define foreign keys explicitly with `ON DELETE CASCADE` or `ON DELETE SET NULL`.
- Add indexes for columns used in WHERE, JOIN, and ORDER BY clauses.
- Use composite indexes for multi-column filters: `CREATE INDEX idx_user_status_created ON users(status, created_at)`.
- Avoid EAV (Entity-Attribute-Value) - use JSONB/JSON columns or separate tables.

## Query optimization
- Use `EXPLAIN ANALYZE` to understand query plans. Look for sequential scans on large tables.
- Avoid `SELECT *`: name the columns you need. Helps indexing and reduces transfer.
- Use `LIMIT` with `OFFSET` for pagination, or keyset pagination: `WHERE id > $cursor ORDER BY id LIMIT 20`.
- Use `INNER JOIN` over `WHERE ... IN (SELECT ...)` when possible.
- Use `EXISTS` instead of `IN` for subqueries: `WHERE EXISTS (SELECT 1 FROM orders WHERE user_id = users.id)`.
- Batch operations: `INSERT INTO users (name) VALUES ("a"), ("b"), ("c")` not one at a time.

## SQLAlchemy / ORM
```python
from sqlalchemy import ForeignKey, String, select
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column, relationship

class Base(DeclarativeBase):
    pass

class User(Base):
    __tablename__ = "users"
    id: Mapped[int] = mapped_column(primary_key=True)
    email: Mapped[str] = mapped_column(String(255), unique=True, index=True)
    orders: Mapped[list["Order"]] = relationship(back_populates="user")
```
- Use `selectinload()` for eager loading relationships. Avoid `lazy="subquery"`.
- Use `async with AsyncSession()` with `asyncio`. Use `sync Session()` for CLI/fast tasks.
- Use `session.get(User, id)` for single-record lookup by PK.

## Migrations (Alembic)
- One migration per logical change. `revision --autogenerate -m "add user settings table"`.
- Review autogenerated migrations before applying. They miss renames and constraint changes.
- Never edit already-applied migrations. Create a new migration for the fix.
- Test migrations: `alembic upgrade head && alembic downgrade -1`.

## N+1 query detection
- Watch for: loading a list, then accessing a relationship on each item in a loop.
- Fix with eager loading: `select(User).options(selectinload(User.orders))`.
- Use `joinedload()` for single-item relationships, `selectinload()` for collections.

## Data types
- `TIMESTAMPTZ` not `TIMESTAMP` - always store with timezone.
- `TEXT` over `VARCHAR(n)` with arbitrary limits. Use `VARCHAR` only when there's a business rule (SSN, phone).
- `NUMERIC(12,2)` for money. `DOUBLE PRECISION` for measurements. `INTEGER` or `BIGINT` for counts.
- `JSONB` for flexible/schemaless data, with GIN index for querying inside the JSON.
