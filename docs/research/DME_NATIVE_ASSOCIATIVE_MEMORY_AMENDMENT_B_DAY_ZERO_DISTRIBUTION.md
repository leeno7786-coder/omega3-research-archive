# Amendment B — Day-Zero Distribution: Generally Intelligent, Experientially Empty

**Amends:** `DME_NATIVE_ASSOCIATIVE_MEMORY_ARCHITECTURE.md`  
**Supersedes:** Addendum A where it proposes distributing a graduated factory cortex or factory-learned memory state  
**Date:** 2026-08-13  
**Status:** Product/distribution architecture amendment

---

## 1. Decision

The distributed Omega should **not** ship with a pre-saturated learned memory organ.

It should ship with:

- its immutable/core seeded memories;
- its language and reasoning model(s), which already carry broad general world knowledge;
- the completed DME/Dewey/graph/plasticity/DeepSleep machinery;
- no inherited autobiographical memories;
- no inherited factory-school semantic graph;
- no inherited factory-school traits, preferences, reward history, salience history, or learned personal associations.

The product doctrine is therefore:

> **Omega should ship generally intelligent but experientially empty. Its language organ supplies prior world knowledge; persistent memory begins at first contact and becomes intelligent through operator-aligned experience, autonomous learning, verified application, and consolidation.**

This amendment reverses the earlier idea in Addendum A that a graduated factory cortex should become the distributed baseline.

The factory-school concept remains useful, but only as a release qualification and memory-organ burn-in procedure. The memories produced during qualification are reset before distribution.

---

## 2. Why the reversal is cleaner

The purpose of Omega's persistent memory is not to duplicate all general knowledge already available to the language organ.

Persistent memory exists to accumulate durable, attributed, operator-specific experience:

- who the operator is;
- what the operator does;
- what domains matter to them;
- projects and relationships;
- temporal history;
- preferences and routines;
- which memories repeatedly prove useful;
- which cognitive pathways succeed or fail;
- traits that emerge from repeated evidence;
- capability and mastery growth produced by Omega's own learning loop.

Preloading every distributed Omega with the same learned memory history would place general model knowledge into the wrong substrate and would force Omega to inherit a synthetic past that did not belong to its operator.

It would also create a second problem at shipment: factory learning would modify far more than canonical facts. It would change:

- engram strength;
- salience distributions;
- association strengths;
- novelty expectations;
- reward-prediction baselines;
- retrieval topology;
- learned pathway preferences;
- potentially emergent traits and other pattern-voted state.

Attempting to preserve only selected portions of that learned state while wiping the rest before distribution risks leaving a partially amputated cognition. The distributed system could begin with strengths and associations whose causal history had been removed, or physiology calibrated against memories that no longer exist.

A clean day-zero reset avoids that class of poisoning entirely.

## 4. First contact is the beginning of lived memory

The existing first-wake onboarding system becomes more important under this model, not less.

The live architecture already treats onboarding as the operator's first personal trajectory signal:

- `hud/settings.py` captures operator profile facts;
- `hud/operator_identity.py` makes onboarding one-shot until day-zero reset;
- `hud/operator_onboarding.py` creates dynamic subdomains/mastery gaps, establishes the initial trajectory, and queues an operator-sourced `LEARN`;
- `hud/onboarding_subtopics.py` decomposes operator-selected domains into concrete learnable subtopics.

The intended developmental sequence is:

```text
CORE SEEDS

    |
```

The operator's profile is not merely metadata. It determines the direction in which Omega begins converting broad model knowledge into durable personal mastery.

## 5. Onboarding should build durable mastery, not relearn basic definitions

The current subtopic decomposition prompt tells the model that Omega has "NO stored knowledge" of each selected domain.

Under this amendment, that statement should be interpreted narrowly: Omega has **no durable memory/mastery record yet**, not that the language organ has no conceptual knowledge of the domain.

The future prompt/contract should ask the language organ to identify what Omega should **durably learn, practice, apply, and retain** to become useful to this operator.

Example:

```text
Operator occupation:
  Robotics Engineer

Declared interests:
  UAV autonomy
  embedded systems
  control theory

Language organ already knows these domains broadly.

Memory task:
  create concrete mastery gaps whose durable acquisition
  would make Omega more capable for this operator.
```

Possible learning map:

```text
UAV autonomy
  -> trajectory planning
  -> degraded communications
  -> swarm coordination
  -> state estimation
  -> sensor fusion
  -> autonomous mission planning
```

The distinction is important:

> **General conceptual knowledge may exist in model weights; durable operator-aligned mastery does not exist until Omega learns and records it.**

## 6. Autonomous learning becomes the semantic-saturation mechanism

The earlier factory-cortex plan attempted to saturate DME before distribution.

The revised design lets semantic topology saturate naturally from the operator's world.

Omega's autonomous loop already knows how to turn mastery gaps into learning pressure. After onboarding, the system can repeatedly:

```text
identify gap
   -> LEARN
   -> ingest attributed knowledge
   -> canonicalize
   -> write Dewey memory
   -> build DME/graph topology
   -> APPLY
   -> VERIFY
   -> receive outcome
   -> reinforce/depress useful pathways
   -> DeepSleep
```

This means the earliest semantic topology is inherently aligned with the operator.

A software engineer's Omega becomes dense in software, systems, projects, tools, and concepts relevant to that person's work.

A physician's Omega develops a different memory topology.

A student, designer, researcher, business operator, or hobbyist produces another.

The memory organ becomes individualized from its first non-seed writes rather than beginning from a generic factory history.

## 7. Google Workspace is the optional acceleration path

The approved Google Workspace alignment architecture remains a major accelerator of personal genesis.

If authorized, Omega can ingest the complete user-selected Workspace corpus through the lawful memory path:

```text
Workspace observation
  -> SourceLedger
  -> Guardian external-ingress screening
  -> durable queue
  -> cognition
  -> episode SRAM
  -> DeepSleep
  -> canonical filesystem
  -> graph / DME projection
```

This can rapidly provide historical evidence about:

- projects;
- collaborators;
- organizations;
- documents;
- communications;
- schedules;
- recurring responsibilities;
- task patterns;
- terminology;
- temporal changes;
- working conventions.

Workspace therefore accelerates autobiographical/operational alignment without requiring factory memories.

The product still follows the existing epistemic rule:

> **Workspace evidence is observation, not reward and not operator instruction.**

Frequency can strengthen evidence that a relationship exists, but it must not be converted directly into preference, dopamine reward, or autonomous authority.

---

## 8. Traits and persona must develop only from the real operator history

This amendment is especially important because Omega develops traits over time through accumulated patterns and evidence.

Factory schooling followed by a partial wipe would risk allowing synthetic educational history to influence:

- trait voting;
- persona evolution;
- salience;
- preference inference;
- relational assumptions;
- learned retrieval pathways;
- behavioral expectations.

Even if factory memories were removed before shipment, derived state could remain unless every downstream adaptive system were perfectly rewound.

That is an unnecessary risk.

The clean doctrine is:

> **No distributed Omega should inherit traits, persona evidence, personal salience, preferences, routines, or experiential associations generated before meeting its operator.**

Core constitutional identity is seeded deliberately.

Everything that makes the installed Omega an individual develops afterward.

---

## 9. Early plasticity should be conservative, not absent

A clean memory organ reintroduces genuine low-history physiology at first contact. That does not require pre-training the memory and then wiping it.

Instead, the system should use developmental gating.

Immediately active:

- canonical memory formation;
- deterministic structural relations;
- DME indexing;
- direct/structural recall;
- RecallVerifier;
- StrengthIndex registration/touch;
- activation tracing;
- operator-directed autonomous learning.

Initially conservative:

- strong positive/negative association reinforcement;
- preference inference;
- persona/trait promotion;
- aggressive forgetting;
- high-confidence personal prediction;
- strong autonomous behavioral shortcuts.

As verified episodes accumulate and personal RPE/novelty statistics stabilize, experiential plasticity can anneal toward its full operating range.

This produces a genuinely operator-conditioned calibration instead of importing factory physiology.

---

## 10. The language organ handles general semantic cold start

A blank persistent memory does not mean Omega loses general semantic competence.

The resident language organ remains capable of interpreting novel language and broad world concepts. It can supply **bounded symbolic routing cues** to the memory engine without owning memory retrieval.

At first contact, before DME has developed rich associative topology, recall may rely more heavily on:

- exact/canonical coordinates;
- entities;
- morphology/fuzzy registry resolution;
- structural Dewey relationships;
- bounded language-organ cue canonicalization.

As Omega lives and learns, DME progressively acquires:

- repeated aliases;
- entity relationships;
- temporal structure;
- contextual associations;
- operator-specific terminology;
- learned pathways;
- verified experience-conditioned shortcuts.

The system therefore shifts naturally from model-assisted cue entry toward richer native pattern completion without needing a preloaded semantic memory graph.

The existing epistemic boundary remains:

> **CUE != CLAIM.**

Language-generated cues may route retrieval. They do not become factual memory without canonical evidence.

## 11. Factory school becomes release qualification, not distributable memory

The curriculum idea remains valuable, but its purpose changes.

Before release, Omega AI can boot a clean instance and run controlled curricula covering:

- language and paraphrase;
- math;
- science;
- computing;
- temporal reasoning;
- causal reasoning;
- knowledge updates;
- contradiction handling;
- zero-overlap semantic recall;
- multi-hop recall;
- plasticity causality;
- DeepSleep consolidation;
- NPU/DME performance.

Every lesson must traverse the real production cognition/memory loop.

The objective is to prove:

> **Can a genuinely clean Omega learn correctly from day zero?**

This provides stronger evidence than shipping the resulting learned state.

The release procedure is:

```text
BUILD SOFTWARE + MEMORY ORGAN
       |
       v
BOOT CLEAN QUALIFICATION OMEGA
       |
       v
RUN CONTROLLED SCHOOL CURRICULUM
       |
       v
MEASURE LEARNING / RECALL / PLASTICITY / SAFETY / NPU
       |
       v
PASS GRADUATION / RELEASE GATES
       |
       v
DAY-ZERO RESET
       |
       v
VERIFY CORE SEEDS ONLY
       |
       v
PACKAGE + DISTRIBUTE CLEAN OMEGA
```

Factory school is therefore analogous to destructive hardware qualification or integration testing: the tested specimen proves the design, but its accumulated test history is not customer state.

A separate clean release image is produced after the same software version passes qualification.

## 12. Qualification gates

The school/burn-in suite should establish that the clean memory organ can grow without embeddings and without early corruption.

Useful release gates include:

- canonical write correctness from record #1;
- zero silent misroutes;
- zero unverified admissions;
- semantic/paraphrase recall curves as memory grows;
- zero-overlap recovery progression;
- knowledge-update/supersession correctness;
- contradiction/negation correctness;
- multi-hop recall progression;
- activation-trace correctness;
- positive/negative/neutral plasticity causality;
- early-episode plasticity stability;
- DeepSleep consolidation correctness;
- deterministic rebuild from canonical state;
- day-zero reset correctness;
- DME/NPU exactness and placement proof;
- sustained latency/throughput/power behavior.

The most important product-specific test is not the final school score alone.

It is the developmental curve:

> **Does a clean Omega become more durable, semantically connected, and capable as experience accumulates without poisoning its own early topology?**

## 13. Day-zero reset becomes a first-class release invariant

Because qualification intentionally creates real learned state, the reset path must itself become release-critical.

A distributable reset must prove removal of all non-core educational history, including:

- canonical school memories;
- school-generated graph edges;
- DME seats/planes derived from school memory;
- association-strength state;
- school-specific StrengthIndex records;
- active/pending eligibility traces;
- school episode/journal state that should not ship as semantic/personal history;
- mastery state created by the qualification curriculum;
- learned trajectories;
- emergent traits/trait observations;
- preference/persona evidence generated by the school;
- temporary neuromodulatory history that would bias the new operator.

What survives must be explicit and small:

- ratified constitution/core seeds;
- code/configuration;
- deterministic memory geometry;
- empty/reinitialized projection state;
- only the minimal system state required for lawful first boot.

The release image should include an automated proof that the memory organ is at the intended day-zero state.

---

## 14. Software upgrades preserve the individual's lived memory

Dropping the distributed factory cortex removes the hardest overlay/versioning problem raised in Fable 5's second review.

There is no generic factory-memory v2 that must be merged underneath millions of personal edges.

However, coordinate stability remains important for a different reason: **software upgrades must not invalidate an existing individual's personal memory.**

Therefore:

- stable semantic/memory identifiers should remain stable across compatible software releases;
- an address already used by a user's persistent memory must never silently change meaning;
- geometry-breaking upgrades require an explicit deterministic migration map and parity verification;
- upgrades should modify capability without replacing the user's lived canonical memory.

The individual should survive software/model/runtime upgrades.

This is a stronger product property than replacing a generic factory cortex beneath them.

## 17. Revised research thesis

The DME-native memory research now has a cleaner product interpretation:

> **Omega is not distributed with an artificial memory of the world. It is distributed with a generally capable language/reasoning organ, a small constitutional memory, and a blank durable experiential substrate. The operator's first-wake profile supplies the first personal direction of growth. Optional Workspace ingestion rapidly establishes attributable history. Autonomous learning converts broad prior knowledge into operator-relevant durable mastery. DME, graph topology, StrengthIndex, neuromodulation, and DeepSleep then become progressively more capable because they are shaped by the individual's actual experience.**

This model avoids inherited factory bias, synthetic trait formation, partial-memory amputation at shipment, and cross-version factory-overlay complexity.

It also returns Omega to its central architectural premise:

> **Persistent memory is valuable because it is lived, attributable, durable, and cumulative — not because it duplicates what the language model already knew before first contact.**

The next DME-native implementation review should treat the following as product requirements:

1. The no-embedding memory organ must function correctly from the first non-seed write.

The distributed product is therefore **not a graduated-memory Omega**.

It is a **day-zero Omega with mature cognitive machinery**.

Its general intelligence comes from its language/reasoning organs.
