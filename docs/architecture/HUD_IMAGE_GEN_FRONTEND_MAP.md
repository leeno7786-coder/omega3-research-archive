**Required change:** Replace `window.OmegaUI.createImage(p)` with a POST to `/api/chat` carrying `{text: p, intent: "IMAGE_CREATE"}`.

The legacy direct endpoint `/api/image/generate` (lines 15448–15477, `window.Build.generate`) is the old HUD-only path and must NOT be used for the create-panel flow once the new frontend lands.

### 1c. Inline result — where to render
After the POST to `/api/chat` returns, the response JSON shape is:

```json
{
  "ok": true,
  "message": "",
  "image": {
    "path": "guardian/state/images/2026-06-08/143052_slug.png",
    "url": "/api/images/2026-06-08/143052_slug.png",
    "prompt": "...",
    "width": 512, "height": 512, "steps": 8, …
  }
}
```

The HUD server already rewrites `image.path` → `image.url` at `hud/server.py:3097–3099`.

**Render target:** append to `#feed` exactly where `OmegaUI.createImage` currently calls `this.appendImage(result.url, '↳ ' + prompt)` (line 16953). That means:
- On success (`result.ok && result.image && result.image.url`): call `this.appendImage(result.image.url, '↳ ' + prompt)` **and** append a "Saved to Settings" note line.
- On failure (`!result.ok`): `this.appendLine('system', '✗ image generation: ' + result.error)`.

The "Saved to Settings" note is NEW — add a single `appendLine('system', '↳ image saved — view in Settings → Created Images')` after the image render.

### 2c. `_renderCreatedImages(panel)` — suggested implementation surface
- **Fetch:** `GET /api/images` (`hud/server.py:2841`)
- **Empty state:** when `count === 0`, show a centered hint: "No images generated yet. Use the create button in the composer."
- **Grid:** thumbnail grid (`<img src="${it.url}">`) with:
  - Prompt text (if returned by backend — currently `list_generated_images` does NOT return prompt; consider extending `runtime/image_store.py:list_generated_images` to also read a sidecar `.json` or parse the filename slug if you want prompt display).

## 3. Backend API summary (already implemented)

| Endpoint | Purpose |
|----------|---------|
| `POST /api/chat` | Cognition-led image generation. Body: `{text, intent:"IMAGE_CREATE"}`. Returns `{ok, image: {url, …}}`. |
| `POST /api/image/generate` | **Legacy** direct HUD endpoint. Still used by `Build.generate`. Do NOT use for the create-panel flow after the refactor. |
| `GET /api/images` | List gallery. Returns `{ok, count, images: [{date, name, url, size, mtime}]}`. |
| `GET /api/images/{date}/{name}` | Serve a single PNG. |

The cognition-led path (`/api/chat` + `intent:IMAGE_CREATE`) is the canonical one; the legacy direct endpoint is retained for backward compatibility with any external callers of `Build.generate`.
